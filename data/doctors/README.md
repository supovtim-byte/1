# Данные врачей

Один файл `<id>.json` на специалиста. В репозитории находятся только сведения для публикации; содержимое `deferred` тоже публично, хотя пока не выводится на сайте. Не добавляйте сюда рабочие заметки, сведения о пациентах, контакты сотрудников, номера личных документов и неподтверждённые предположения.

## Обновление

1. Измените JSON врача или создайте новый файл по образцу `hodykina.json`. Идентификатор `id` совпадает с именем файла и определяет адрес `dist/doctor-<id>.html`; после публикации его лучше сохранять.
2. Для каждого факта укажите `sourceRefs`: идентификаторы записей из `sources` этого же файла. Текст для читателя находится в `text`, `label`, `title` и других содержательных полях. URL, название источника и дата проверки хранятся отдельно в `sources`. Удалённые сайты при сборке не запрашиваются.
3. Выполните из корня репозитория `npm run build`, затем `npm run check` (Node.js 24). Зафиксируйте данные и получившиеся HTML. После отправки в `main` существующий workflow GitHub Pages повторит генерацию и проверки и опубликует `dist/`.

Сборка не требует установки зависимостей. Команда `npm run check:doctors` проверяет актуальность HTML без перезаписи и запускает тесты. Не редактируйте сгенерированные страницы вручную: общее оформление меняется в `templates/doctor.html`, каталог — в `templates/doctors.html`. Исходный шаблон взят из страницы Ходыкиной; адаптивные стили остаются общими.

## Поля

| Поле | Назначение |
| --- | --- |
| `schemaVersion`, `id`, `order`, `name`, `aliases` | Версия схемы, устойчивый адрес, порядок, полное имя и прежние короткие имена для карточек на других страницах. |
| `specialties`, `filterTags` | Подтверждённые специализации и ключи фильтров каталога. Доступные ключи определены в `scripts/generate-doctors.mjs`. |
| `publication.catalog` | Показывать ли специалиста в каталоге. Страница создаётся для каждого JSON независимо от этого флага. |
| `publication.bookable`, `availabilityLabel` | Можно ли предлагать запись именно к этому врачу; при `false` страница предлагает связаться с клиникой. Причины из личной жизни не публикуются. |
| `photo` | `null`, пока нет фотографии; иначе объект `path`, `alt`, `width`, `height`. Путь относительно `dist/`, например `assets/doctors/hodykina/portrait.webp`. |
| `about`, `education` | Абзацы о враче и образование (`year`, `text`, `sourceRefs`). Пустой массив скрывает блок. |
| `experience` | `null` либо `years`, дата актуальности `asOf` и `sourceRefs`. Подтверждённые числа берутся из профессиональных карточек. Для согласованного пересчёта опубликованного стажа используется дополнительный объект `calculation`: исходное число, дата публикации, полные прошедшие месяцы, округление вниз и предположение о продолжении практики. По согласованию с владельцем сайта для семи специалистов без опубликованного стажа добавлена оценка от первой профильной квалификации или аккредитации; фактическое начало работы при этом не подтверждено. Значения не увеличиваются автоматически при сборке. |
| `directions` | Группы `title`, `sourceRefs`, `items`. У пункта — `label`, `href` на раздел услуг/цен, `kind` и `sourceRefs`. `kind` принимает `procedure` (процедура), `method` (метод работы) или `consultation` (консультация). Для процедур и методов нужен персональный профессиональный источник; должность, диплом и отзывы пациентов сами по себе их не подтверждают. Не назначайте врачу весь набор услуг клиники по одному названию специальности. |
| `reviews.links` | Ссылки `{ "sourceRef": "reviews" }` на источники с `kind: "review_platform"`. Карточка показывает площадку и переход к отзывам; чужие тексты, авторы, даты и общий рейтинг не выдумываются. Пустой список скрывает блок. |
| `documents` | Публичные документы: `path`, `title`, `sourceRefs`. Локальные файлы хранятся в `dist/assets/doctors/<id>/`. Сейчас список пуст; блока документов в HTML нет. |
| `deferred` | Награды (`achievements`), публикации (`publications`), клинические случаи (`clinicalCases`), места работы (`employment`) и исторические значения стажа (`experienceHistory`). Сохраняются для будущих блоков, в HTML не попадают. |
| `sources` | Справочник `{ "идентификатор": { "label", "url", "kind", "checkedAt" } }`. Только публичные HTTPS-ссылки, без учётных данных. |

В превью генератор выводит фамилию и имя из полного `name`; на странице врача сохраняется полное ФИО. Краткие подписи специализаций формируются автоматически: например, «Терапевт, детский стоматолог», без повторения «врач-стоматолог» перед каждой ролью. Общая роль «Стоматолог» скрывается рядом с более конкретной. Полные исходные названия в `specialties` сохраняются.

«Направления работы» показывают только подтверждённые процедуры и методы конкретного специалиста. Консультации остаются в JSON, но в этот блок не выводятся; если других сведений нет, блок скрыт целиком. Отсутствие блока означает отсутствие подготовленных персональных сведений, а не ограничение квалификации врача. Для публикации методов использованы индивидуальные описания врачей на сайтах клиник и опубликованные самой «Метелицей» клинические случаи. Общие услуги других клиник и цены оттуда не переносятся. Ссылки из пунктов ведут к соответствующим разделам общего прайса «Метелицы».

У трёх специалистов, для которых официальный сайт сообщает о временном отсутствии приёма, сохранены страницы и карточки, но отключено предложение записи к конкретному врачу. Для шести врачей по просьбе владельца сайта стаж пересчитан от официального ответа клиники от 17 декабря 2022 года: к исходному значению добавлены 47 полных месяцев до 27 ноября 2026 года, результат округлён вниз до целого числа лет. Расчёт предполагает продолжение практики; исходные числа, даты и метод сохранены в `experience.calculation`. Значение «более 20 лет» использовано с нижней границей 20. Другие найденные сведения о стаже и расхождения между источниками сохранены в данных; средние значения не применяются. По отдельному указанию владельца сайта для пяти оставшихся специалистов стаж рассчитан от первой профильной квалификации, а ещё для двух — Богдановой и Янгалова — от аккредитации 27 июня 2023 года. Это предположение о начале и продолжении практики, а не подтверждённая история трудоустройства; после получения сведений клиники замените число и удалите соответствующий `calculation`. На сайте остаётся общий формат «опыт: N лет».

Основной источник образования — [публичный документ клиники](https://metelitsa-dent.ru/files/Информация_об_образовании_медицинских_работников.pdf); ссылки с номерами страниц находятся в каждом JSON. Для текущего состава и специализаций использован [раздел специалистов](https://metelitsa-dent.ru/about/personal/). Дополнительные профессиональные источники указаны индивидуально.
